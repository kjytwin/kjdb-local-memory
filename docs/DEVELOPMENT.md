# 공개 준비·개발 기록

## 공개 준비 플랜

1. 텍스트 메모리 native 저장소, stdio 모듈, 설정 생성기, 실제 회귀 테스트만 선별한다. 기존 비공개 저장소의 Git 이력·개인 문서·DB·앱 설정·원본 로그를 가져오지 않는다.
2. 사용자용 README·설치 안내·앱별 설정 안내·한계·MIT·개발 빌드·CI를 정리한다.
3. 새 source/fault DLL과 새 ZIP으로 실제 저장·복구·추출 패키지 검증을 한다. 두 차례 자체 검토와 가상 상사의 지적 최대 3개를 기록한다.
4. 선별한 파일만 새 Git 이력으로 올린다. 기존 저장소의 공개 범위는 바꾸지 않는다.

## 구현 선택

기존 메모리 형식과 저장·복구 코드를 재사용한다. MCP 모듈에서 이 제품에 포함되지 않는 토큰 엔진용 진입 경로와 기본값만 제거한다. 사용자-facing 진입점은 tools/local/kjdb_local.py다.

프로젝트마다 서버 하나를 사용하는 원칙은 유지한다. 범위를 넓히기 위해 요청마다 락을 바꾸거나 자동 복구·자동 재시도를 추가하지 않는다. 사용자 설정은 생성된 제안을 검토해서 등록한다.

## 자체 검토 1

- 서버 진입 경로와 설정 생성기, native 라이브러리 경로가 새 폴더에서 완결되는지 확인한다.
- 외부 런타임 고지는 별도로 보존하고 MIT에 판매 금지 조건을 덧붙이지 않는다.
- 기존 실사용 결과를 새 공개 소스의 앱 실사용 결과로 표시하지 않는다.

## 자체 검토 2

- 공개 allowlist와 최초 커밋 파일을 대조한다. 임시 인증 확인 코드·환경 파일·사용자 DB·개인 설정·원본 로그가 포함되지 않는지 확인한다.
- 사용자 설치 문서와 추출 ZIP의 실행 경로를 함께 검사한다.
- 오류·SKIP·미검증을 유지하고 실제 실행 결과만 VALIDATION.md에 기록한다.

## 가상 상사 박서준 — 자체 역할 검토

1. **새 공개 저장소에 비공개 이력이 따라오지 않는가?** 기존 .git을 복사하지 않고 선별된 텍스트 파일로 최초 커밋을 만든다.
2. **설정 생성과 실제 AI 사용을 혼동하지 않는가?** 공개 스냅샷의 native/프로토콜 검사와 기존 패키지의 앱 실사용을 분리한다.
3. **미리보기를 안정판으로 안내하지 않는가?** README·변경 기록·검증 범위·패키지 메타데이터에서 일관되게 preview라고 표시한다.

두 검토와 가상 역할은 독립적인 사람의 외부 검토가 아니다. 발견된 실제 문제는 수정하고 관련 지침을 AGENTS.md에 남긴다.

## 공개 준비 결과

- 최초 43개 파일을 명시된 공개 목록과 비교했다. 새 Git의 최초 커밋에는 부모가 없고 작성자 이메일은 GitHub noreply 주소를 사용한다. 기존 비공개 이력은 포함하지 않는다.
- 21개 native/stdio/클라이언트 설정 회귀 검사가 모두 통과했고 SKIP은 없었다. 추출된 ZIP의 런타임·MIT·Python 고지·체크섬과 UTF-8 재시작 보존도 통과했다.
- 필요 도구가 PATH에 없던 초기 빌드 시도는 성공 근거에서 제외했다. 설치된 CMake 실행 경로로 production/fault DLL을 새로 빌드했고, PowerShell 명령 부재를 즉시 실패 처리하는 규칙을 추가했다.
- 패키지 메타데이터가 안내하는 PRIVACY·VALIDATION 문서도 ZIP에 포함하도록 수정하고 존재 여부를 검증했다.
- 최종 버전 이름의 점 때문에 Path.with_suffix가 ZIP 이름을 잘라내는 문제를 발견했다. 이름 전체에 .zip을 붙이도록 수정하고, CI도 점이 포함된 출력 경로로 검증하도록 바꿨다.
