# 안정판 준비 검토

## 자체 검토 1: 데이터 보존

- 한도 초과 오류 코드 5, 전후 native 백업과 종료 후 원본 바이트 일치,
  재열기와 첫 메모리 조회를 확인한다.
- Windows의 열린 로그 잠금 때문에 검사 코드의 직접 읽기가 실패했다.
  제품 잠금을 유지하고 native 백업 또는 종료 후 비교하도록 검사 코드를 수정했다.
- 이전 패키지와 새 DLL은 별도 프로세스로 열고, 이전 버전으로 새 기록을 재조회한다.
  복원은 원본을 덮어쓰지 않는 새 폴더에서 수행한다.

## 자체 검토 2: 출시 증거와 배포

- 실제 CLI 결과는 새 프로세스의 구조화된 도구 결과와 본문 해시로 대조했다.
- CI 기준 ZIP을 SHA256으로 고정한다. 기준 패키지 누락은 SKIP이며 필수 합격이 아니다.
- 업데이트·복원 문서를 ZIP에 포함하고 패키지 검사에서 존재를 요구한다.
- Desktop 최신 패키지 실제 호출은 미완료이므로 안정판 완료로 표시하지 않는다.

## 가상 관리자 박서준: 검토 역할극, 외부 승인 아님

1. **복원이 기존 데이터를 덮어쓰는가?** 새 루트에 복원하고 원본을 보존하도록
   문서화했다. 버전별로 검증한 호환성만 적용한다.
2. **잠금을 풀어 테스트를 통과시켰는가?** 잠금은 그대로다. 검사에서 native 백업과
   종료 후 비교를 사용하도록 고쳤다.
3. **CLI 통과를 Desktop 합격으로 세었는가?** 결과를 분리하고 Desktop 검증을
   안정판 필수 잔여 항목으로 유지했다.

## 최종 검토 보완

- Desktop은 사용자 제공 본문·UUID 결과와 후보 재시작·도구 호출 로그로 교차 확인했다.
  로그에서 본문을 직접 확인하지 못한 한계를 VALIDATION.md에 명시했다.
- 안내에 프로젝트 ID를 빠뜨려 default 요청이 거부되었다. 프로젝트 ID를 명시해
  정정했고, 사용자용 테스트 문구에 프로젝트 ID를 반드시 넣도록 AGENTS.md에 추가했다.
- 최종 ZIP의 실행 파일 전체를 후보와 대조한다. 문서·메타데이터 변경에 대해
  실제 앱을 다시 실행했다고 표현하지 않는다.
